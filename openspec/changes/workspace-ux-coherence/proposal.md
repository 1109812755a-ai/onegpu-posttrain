# Proposal

## Why

工作区功能已覆盖数据准备、五阶段训练、独立评测、Runs 与分析，但持续追加的局部界面让配置、预检、执行、日志和结果在不同位置以不同方式呈现。用户会把长时间运行误认为卡住，也难以从大量内部 ID、状态提示和原生控件中识别当前任务与下一步操作；在交付前需要一次以真实任务为中心的体验收束。

## What Changes

- 保留“数据 / 训练与评测 / 实验 Runs / 分析与改进”主导航和现有深链接，建立跨页面一致的任务上下文、步骤、主操作和返回路径。
- 先整理训练与评测：配置、只读预检、确认、已启动、运行、完成/失败分别使用清楚且互斥的状态；启动成功即提供精确 Run 入口，长任务持续展示已用时间、最近更新、进度可用性和日志/结果入口，不以一直显示“处理中”代表后台运行。
- 将模型/数据名称、状态和可执行下一步置于首层；ID、hash、协议、原始配置和完整日志保留但默认按需展开。阻断信息指向恢复动作，不能掩盖其他可用功能。
- 统一表单、按钮、卡片、提示、状态徽标、留白与响应式规则，消除 Runs/Launcher/数据页面之间明显的原生控件和局部样式差异；不改变质量、许可、lineage 与 GPU 安全门禁。
- 用导入/登记到训练、训练到评测、Run 到模型交接、分析到定向补数的真实浏览器路径验收桌面、390px、键盘、刷新/返回、长任务、接口失败和一次性预检令牌失效。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `web-workspace-ux`：增加跨模块任务状态表达、单一下一步操作、长任务反馈、诊断信息层级与一致的控件/响应式行为要求。

## Impact

- 前端主要涉及 `web/src/Launcher.tsx`、`Runs.tsx`、`DatasetWorkbench.tsx`、`ActivityTasks.tsx`、`WorkspaceNavigation.tsx`、`main.tsx` 与 `style.css`；模型体验和分析页面按共享规范审视并分阶段迁移。
- 可能需要复用现有只读 Run/任务状态接口或补齐前端轮询/恢复状态；不新增训练启动协议、不改变评测计算、数据登记格式和已持久化 artifact。
- 更新前端交互测试、浏览器任务走查与中文使用说明；与在建的 `stage-training-evaluation-workbench` 7.3 验收互相衔接，避免将测试通过误称为视觉/交互验收完成。
