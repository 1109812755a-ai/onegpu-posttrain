# Design

## Context

见 `proposal.md`。当前前端为 React 单页工作区，`main.tsx` 路由到数据、`Launcher`、`Runs`、分析等页面；`ActivityTasks` 已能显示活动任务，Run API 已提供状态、日志、时间及身份。`Launcher`、`Runs` 等页面分别维护预检/提交 busy 状态和任务视图，`style.css` 则有大量页面局部选择器与增量色值。现有 OpenSpec 变更已规定四主导航、深链接、GPU 门禁及预检一致性，本变更只收束呈现，不重定义那些协议。

## Goals / Non-Goals

**Goals:**
- 让用户在每一步知道对象、当前状态和唯一主操作；网络请求与后台长任务使用不同状态。
- 让 Run 成为训练/评测执行的共享事实来源，刷新与跨模块导航不丢失已启动任务。
- 建立可复用的字段、操作栏、任务状态、提示和证据折叠样式，先覆盖训练/评测/Runs，再扩展数据与分析。
- 以真实任务而非组件快照检验可用性、窄屏和键盘路径。

**Non-Goals:**
- 不改训练/评测算法、Profile 白名单、数据许可和质量判定、GPU 锁或一次性确认令牌语义。
- 不引入自动重试、后台队列、自动启动评测或跨设备任务同步。
- 不把所有技术证据删掉或用前端推断替代后端状态。

## Decisions

### 1. 以任务状态模型驱动呈现，而非以按钮 busy 驱动整个页面

前端区分 `editing`、`preflight_pending`、`preflight_ready/blocked`、`submit_pending`、`run_starting/running`、`run_terminal`。`submit_pending` 只覆盖一次启动请求；收到 Run ID 后立即转为 Run 状态卡，轮询现有只读状态接口。失败/超时但服务端可能已启动时，先按可追溯对象与活动任务查询状态，不能盲目重提 POST。可用状态和下一步操作从后端 Run/预检证据推导，避免两个页面各自维护永久的“处理中”。

备选为继续给每个按钮加临时提示；它不能解决刷新、跨页面和长任务状态不一致，因此不采用。

### 2. 以同一视图骨架组织任务，而不是把所有字段一直展开

主要页面采用“对象上下文（阶段/模型/数据/Run）→ 步骤与当前操作 → 运行/结果 → 可展开证据”的层级。阶段训练可保留默认参数的简洁路径，高级参数与身份摘要展开；Run 详情首屏展示状态、关键输入/输出及下一步，完整 lineage、路径、原始协议和日志留在二级区域。每个步骤只突出一个主按钮，关联导航与诊断为次要操作；阻断和错误始终就地可见。

备选为重做全部路由和后台流程；风险与回归面过大，也违背现有跨模块对象身份设计，因此保留当前四主导航和 URL 协议。

### 3. 共享视觉语义，逐页迁移

从现有 CSS 抽取少量语义 token（surface、text、muted、border、primary、success、warning、danger、focus、spacing），建立一致的表单/选择器、按钮层级、提示、状态徽标和任务卡样式；先迁移 `Launcher`、`Runs` 的训练/评测流程，再迁移 `DatasetWorkbench` 与分析中同语义控件。保留现有明/暗/随系统主题，避免一口气重写所有 CSS。共享组件只处理视觉与状态展示，页面继续负责 API/路由和领域校验。

备选为每页继续增补专用 CSS；这正是现有风格漂移的来源，不采用。引入新 UI 框架也会增加依赖和迁移成本，首轮不采用。

### 4. 任务反馈以可信数据为界

计时用服务端开始时间计算，最近更新使用服务端状态/日志时间；若没有新的心跳或进度，不称其为“实时推进”。进度只有后端有可靠分子/分母时才展示百分比，否则标为未知并提供日志。启动、训练完成、评测完成分别与精确 Run 身份关联；离线、接口错误、一次性令牌失效显示重试预检/查看现有 Run 的恢复路径，不自动重启。

备选为前端本地计数和乐观完成动画；会误导用户，尤其在 20 分钟以上 GPU 评测期间，不采用。

## Risks / Trade-offs

- [多个现有页面有不同状态 DTO] → 先建立展示适配层和枚举映射，保留后端状态原值用于诊断；未知状态显示“状态待确认”，不得映射为成功。
- [请求超时发生在服务端已创建 Run 之后] → 查询活动任务与 Run，禁用自动重提启动；只有确认未创建任务时才允许重新预检。
- [折叠证据可能掩盖安全阻断] → blocker/质量许可/GPU 占用放在当前步骤首层，只有原始详情折叠。
- [视觉迁移引发主题或窄屏回归] → 同时覆盖三种主题、390px、键盘焦点和长 ID/日志溢出，按页面分批合并。
- [与在建工作台 7.3 重叠] → 以本变更交互验收为补充，不擅自将其未完成的真实端到端验收标为已完成。

## Migration Plan

1. 固化现状截图和真实任务清单；定义状态与组件基线。
2. 迁移训练/评测启动及 Runs 详情，保留现有 API、深链接和确认逻辑。
3. 迁移数据/分析的同语义控件与状态反馈；核对主题和响应式行为。
4. 执行前端自动测试、构建及受控浏览器走查，记录仍需真实 GPU/网络的验收项；发现回归时按页面回退视觉层，不回写 Run 或 dataset artifact。
