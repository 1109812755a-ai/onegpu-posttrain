# Proposal

## Why

用户目前只能通过固定评测样本或查看训练日志间接感受阶段模型差异，难以用自己的问题直观体验 CPT、SFT、DPO、SimPO、GRPO 等阶段产物。增加受模型血缘约束的本地对话与同题对照，可以补充定性观察，同时不把聊天误当成正式评测或训练数据。

## What Changes

- 在训练与评测工作区增加独立的“模型体验”视图，并从成功 Run 的已核验模型产物提供“试用此模型”入口。
- 支持选择一个本地可加载模型进行多轮对话；支持将相同问题最多提交给 3 个模型并排比较，按顺序加载/推理/卸载模型，不并发占用 GPU。
- 仅开放模型 ID、阶段、摘要和本地路径均可核验且兼容推理的模型；明确显示模型来源、资源状态、生成参数和失败原因。
- 与训练和评测共用本地 GPU 互斥约束；对话内容默认只用于交互，不自动建立 Run、评测结论或训练数据，保存/导出需显式操作。
- 将聊天与正式评测区分：聊天输出是定性体验，不产生正式指标，也不声称事实正确或质量已验证。

## Capabilities

### New Capabilities
- `model-playground-chat`: 受模型身份/血缘约束的本地模型单聊与最多三模型同题对照。

### Modified Capabilities
- `web-workspace-ux`: 增加模型体验工作区入口、Run 到模型体验的上下文交接，并明确窄屏与操作状态行为。

## Impact

涉及 `src/onegpu_posttrain/ui` 的核验模型发现、受控推理与 GPU 互斥 API，`web/src` 的训练模块导航、模型体验页和 Run 详情入口，以及相应 API/前端测试。复用现有模型产物/lineage 与本地 Transformers 推理能力；不新增远程 Provider、训练框架、评测指标或自动数据登记流程。
