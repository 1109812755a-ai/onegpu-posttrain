# Proposal

## Why

合成数据的目的不仅是补足训练数量，还包括训练后根据诊断评测发现薄弱场景，定向补充相关数据，再检验目标能力和其他能力是否变化。项目需要一条能在单卡、本地文件和可选外部模型条件下复现的“诊断 → 生成 → 验证 → 训练 → 复测”路径，并记录没有提升或出现退化的结果。

## What Changes

- 依赖先行变更 `data-policy-experiments` 的策略、固定来源/分组、实验登记和效果比较；首个生成切片面向数学 SFT 与正确性排序 Preference，不要求数据库、调度器或自动飞轮。
- 新增版本化场景切片、诊断报告与定向补数计划：引用真实 eval/model/protocol，报告场景分母、解析/评分问题及目标差距，记录用户事先设置的阈值、训练种子来源、数据预算和保护指标。
- 将诊断开发集与最终留出评测集明确分工。生成默认只接收抽象场景描述和隔离的训练种子，不把评测题及其答案/改写作为训练材料；缺少独立复测数据或检查证据时不能宣称闭环已验证。
- 提供可选、可配置的模型生成接口：用户配置 endpoint、model、凭据环境变量名、提示词模板、输出格式及调用预算。首版支持一个 OpenAI-compatible 协议 adapter 和本地 fake adapter；生成必须由显式 CLI 启动，配置/预览不会消费调用额度。
- 从训练问题生成短而完整的候选答案，或为同一问题生成多个候选并经独立验证构造 Preference；每个结果通过格式/长度、去重、污染和策略检查，保留失败与未验证状态。完全新题须有独立可检验的 reference，不能仅凭模型自报答案视为正确。
- 支持“经验证 / 未验证 / 受控注入噪声”实验数据，记录具体干预而非主观好坏标签；首版噪声针对支持的 SFT 答案扰动，Preference 使用验证后候选，不默认注入错误排序。
- 记录生成模型、提示词/配置摘要、输入祖先、候选响应、验证、采集成本和新数据/训练/评测血缘；支持缓存与中断后恢复，不能承诺远程模型再次调用逐字重现。
- 前端在现有 Data/比较区域增加场景缺口、生成计划配置/导出、配额/成本与验证产出视图，展示目标场景和通用保护指标的真实复测结果。闭环训练与远程生成仍显式通过 CLI 执行，自动启动由后续 launcher/调度变更决定。

## Capabilities

### New Capabilities

- `targeted-data-planning`: 根据有分母和协议的诊断评测登记薄弱场景、训练种子、生成目标及不污染最终评测的复测计划。
- `synthetic-data-generation`: 配置可选生成供应方、格式/验证协议、调用预算和恢复缓存，并将候选转为具备质量状态、成本和完整来源的数据版本。

### Modified Capabilities

无。复用先行变更的 `dataset-policy`、`data-policy-comparison`、`data-policy-editor`，不复制通用比较和 UI 编辑要求。实施前须确认这些依赖已落地；主规格尚未同步时以已审阅的先行 delta 为明确依赖。

## Impact

- 新增场景报告、生成计划、provider adapter、候选验证/导出和闭环汇总模块；复用 `evaluation/internal_math.py` 的 predictions、`evaluation/answers.py` / math-verify 的验证入口及已有数据 writer/lineage。只有总分且无题目结果/分组证据的历史 eval 不能虚构场景准确率。
- 新增可选生成 extra、CLI 计划/dry-run/执行/汇总入口；核心安装和原有开源数据/本地导入流程不依赖 API 或账户。mock 测试不需要网络、凭据、GPU 或真实费用。
- 通过现有 `data_build` run 和显式 `llm_generate` transform 连接生成操作，避免为首版强制重写 lineage v1；prompt、原始响应等保留在受限本地产物，公开/UI 接口仅展示白名单摘要。
- 配置只保存凭据变量名，不保存密钥或带密钥 URL；新产生的数据与报告使用独立目录，不覆盖历史数据。生成内容的来源/使用条款声明沿用项目开源资产规则，不自动继承仓库许可证。
- 实施时更新中英文数据质量/处理效果设计、前端/开发/开源路线与中文操作指南，明确本次提前交付的窄范围、已验证/未验证边界、诊断与留出评测角色，以及生成/训练成本和无收益结果的报告方式。
