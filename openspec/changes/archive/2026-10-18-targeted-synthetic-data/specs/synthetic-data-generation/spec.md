# Spec Delta

## Purpose

通过可选且明确配置的模型供应方生成阶段训练候选，经过可解释验证、选择和版本化导出后接入现有训练数据体系。每次生成保留输入祖先、模型与提示词证据、预算及失败记录，使定向补数和质量对照能够在不依赖专有服务的核心项目中被复查与复用。

## ADDED Requirements

### Requirement: 生成配置明确且凭据不落入公开产物
系统 MUST 接受明确的 provider/endpoint/model、凭据变量引用、提示词模板、输出协议、生成参数及预算；密钥只能在实际调用时解析，不能保存到计划、日志、UI、异常或导出报告。

#### Scenario: 缺少凭据执行生成
- **WHEN** 远程生成所需凭据变量不存在
- **THEN** 执行前报明确缺失且不发请求，配置和错误不包含任何秘密值

#### Scenario: 配置含带密钥的 URL
- **WHEN** endpoint 包含内嵌认证或被识别的敏感查询字段
- **THEN** 配置校验拒绝并要求独立凭据引用，不将 URL 原文回显到公开错误

### Requirement: 生成是显式可选操作
系统 MUST 仅在明确执行生成命令时发出模型请求；配置校验、计划保存、dry-run 和页面浏览均无远程调用，核心开源数据/本地导入流程不依赖生成服务。

#### Scenario: 没有 API 账户运行项目
- **WHEN** 用户仅使用开源来源、本地数据或 fake provider
- **THEN** 可以完成相应数据与实验流程，生成能力显示为未配置或本地模拟，不能被误认为远程真实结果

### Requirement: 每次调用计入明确预算
系统 MUST 对请求次数、重试次数、超时、每次输出上限和可用 token/费用观测执行并报告所声明的边界，区分硬请求限制与估算/事后统计；不能以未知费用显示为零或承诺无法保证的计费上限。

#### Scenario: 接口错误持续重试
- **WHEN** 调用失败、限流或返回格式错误并触发重试
- **THEN** 每个实际请求消耗请求预算，达到上限后停止并保留 partial/failed 和 stop reason，不无限生成直到配额达成

#### Scenario: 供应方不返回费用或 token 用量
- **WHEN** 响应缺少相应计量证据
- **THEN** 对应成本字段保持 unknown；可依据用户声明费率提供有标记估算，不作为真实账单或严格费用保证

### Requirement: 输出格式校验独立于语义质量
系统 MUST 使用项目提供的阶段候选格式验证必填字段、非空内容、问题身份和输出可解析性；格式通过后仍独立检查长度、重复、污染及正确性证据，模型自报质量不能成为 verified 依据。

#### Scenario: JSON 合法但答案错误
- **WHEN** 候选符合输出结构但不通过声明的答案验证
- **THEN** 保留格式通过和答案失败两种事实，由对应策略决定拒绝或仅供明确噪声/探索使用，不将其标为高质量

### Requirement: 新问题和未知参考不自我验证
系统 MUST 将答案正确性验证绑定独立可信 reference 或可验证构造过程，记录方法、版本和支持范围；完全新题只有生成模型自报答案或同模型自评时必须保持未验证。

#### Scenario: 验证器不支持答案类型
- **WHEN** reference 缺失、解析失败或验证器不支持当前任务
- **THEN** 结果为 unsupported/unverified 并显示覆盖，不能将异常视为错误答案或把模型自评通过当作独立验证

### Requirement: 候选长度适配目标训练配方
系统 MUST 按目标 tokenizer/模板计量完整候选长度，并执行计划中的训练长度限制；完成原因表明截断或答案缺失时必须如实标注，不默认截断内容来满足配额。

#### Scenario: 简洁提示词仍生成超长答案
- **WHEN** 候选超出目标训练长度
- **THEN** 按策略拒绝或记录探索状态，可在剩余预算内按已登记的修订模板重试，不能承诺简洁提示词保证长度合格

### Requirement: Preference 来自同题且有验证依据的候选
系统 MUST 仅将同一训练问题下满足声明条件的正确/错误候选构造成正确性排序的 chosen/rejected，并保留两侧生成与验证祖先；候选都正确、都错误或含未知时不能伪造满足规则的 pair。

#### Scenario: 多次生成都未产生错误侧
- **WHEN** 某题只有验证正确的候选且调用预算已耗尽
- **THEN** 报告缺错误侧和未满足 pair 目标，可保留 SFT 候选，不能复制相同答案或把未知标签作为错误侧补齐

### Requirement: 质量对照记录可测量的干预
系统 MUST 区分经验证、未验证与 intentionally_noisy 数据，记录实际检查覆盖；受控噪声必须有版本化变换、比例、seed 和祖先，保持训练格式及评测隔离，不能依赖“生成差数据”的提示词自报结论。

#### Scenario: 对 SFT 数据注入已声明答案噪声
- **WHEN** 用户选择支持的答案扰动规则与比例
- **THEN** 从相同源问题构造新数据版本，记录实际被修改/验证不等价的数量和其他内容变化，不把该组标为已验证正确

### Requirement: 缓存恢复区分本地复用与远程不确定请求
系统 MUST 按完整输入、provider/model、提示词/参数/协议摘要和候选序号复用已完成响应，中断恢复保留独立执行记录；超时但可能已受理的请求必须标记 uncertain，不宣称 exactly-once 计费或自动无代价重试。

#### Scenario: 已完成一部分后进程中断
- **WHEN** 用户恢复同一生成计划
- **THEN** 完成且校验通过的缓存不重复请求，未完成项按剩余预算执行；uncertain 项须使用供应方幂等能力或显式重试选择，并记录可能重复费用

### Requirement: 生成数据和成本保持完整来源链
系统 MUST 为生成候选、策略输出与噪声变体保存来源身份、输入祖先、提示词/配置摘要、响应摘要、验证版本、生成 run 及实际成本，关联后续训练模型和评测；原始响应与敏感正文仅保留在声明的本地受限存储。

#### Scenario: 从模型结果追溯生成训练样本
- **WHEN** 用户沿 model → train run → dataset 查看来源
- **THEN** 能追到种子、生成模型/模板、候选、验证及选择策略；UI/公开报告只暴露允许的摘要，不能泄露凭据或受限原文

### Requirement: 远程再次生成不承诺逐字复现
系统 MUST 记录可用模型 revision、请求 seed 支持情况及缺失证据，将持久化响应复用与再次远程调用区分；完成数据版本能按内容摘要验证，远程服务版本未知不能标成固定版本。

#### Scenario: 供应方没有固定模型 revision
- **WHEN** 配置只有可变 model 名称且响应不提供固定版本
- **THEN** provenance 标明该限制，通过保留原始响应和内容摘要支持复查，不声称同 seed 可以重现完全相同输出
