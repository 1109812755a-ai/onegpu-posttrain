# Spec Delta

## Purpose

让用户以版本化策略构建适用于单卡训练的数据，区分数据语义质量、资源适配和探索用途，并用来源、规则、拒绝原因及质量证据解释每个数据版本。策略预览与完整构建共享行为，使小规模实验可复现，同时保留正式 Mini 的独立验收语义。

## ADDED Requirements

### Requirement: 策略具有稳定身份和明确用途
系统 MUST 为策略保存阶段、用途、规则及版本、tokenizer/模板引用、资源限制和解析后配置摘要；改变影响输出的设置 MUST 得到新的策略身份，历史策略不可原位改写。

#### Scenario: 从基线复制实验策略
- **WHEN** 用户复制 SFT 基线并修改一项规则
- **THEN** 新策略引用原策略，保留完整解析配置和差异，生成新身份与摘要，原配置和原数据保持可读取

#### Scenario: 配置包含不支持的阶段规则
- **WHEN** 用户向某阶段提交无适用语义或未知的规则字段
- **THEN** 校验失败并指出字段及适用阶段，不忽略字段或把未实现功能显示成已生效

### Requirement: 质量设置与资源适配独立呈现
系统 MUST 分别呈现正确性/完整性等质量策略、长度/数量等资源预算及固定完整性要求；长度 MUST 按声明的 tokenizer 和渲染模板计量，超长不能直接报告为语义错误。

#### Scenario: 正确候选全部超过长度上限
- **WHEN** 问题存在符合正确性要求的候选但所有候选都超过当前长度限制
- **THEN** 报告长度原因和候选长度分布，保留正确性证据，不把该问题报告为没有正确候选

#### Scenario: 数据长度与训练 recipe 不兼容
- **WHEN** 探索计划声明的完整样本长度超过训练 recipe 可接收长度
- **THEN** 执行前指出不兼容，不默认截断后继续并保留“完整答案”声明；显式截断实验需要新策略和单独标注

### Requirement: 探索策略不伪造验证结论
系统 MUST 允许探索用途按声明规则报告而不筛除部分语义检查失败/未验证样本，并如实记录通过、失败、未知和未测量；正确性排序的 Preference MUST 仍有声明的排序依据，不能将未知标签自动视为错误。

#### Scenario: SFT 探索策略仅记录正确性
- **WHEN** 探索策略将正确性从筛除改为仅报告
- **THEN** 可保留格式和其他必要要求有效的样本，但 metadata、质量报告及界面保留真实验证状态，不能标成 verified

#### Scenario: Preference 没有已知错误候选
- **WHEN** 正确性排序策略只有正确或未知候选而没有已知错误候选
- **THEN** 该题不产生满足此排序语义的 pair，报告缺侧和未知标签数量；不能自动将未知候选作为已验证 rejected

### Requirement: 完整性要求独立于质量宽严设置
系统 MUST 对所有探索和正式策略执行可训练格式、来源及许可可用性声明、引用/摘要完整性、固定评测隔离和污染防护要求；通过质量设置不能关闭这些要求或将缺失检查标成通过。

#### Scenario: 尝试关闭训练评测隔离
- **WHEN** 策略提交关闭隔离或使用固定评测题作为训练输入的设置
- **THEN** 校验拒绝该配置，说明受保护要求，不生成可执行的训练数据策略

### Requirement: 拒绝诊断区分各类原因及统计语义
系统 MUST 分别记录可用候选的正确性状态、完整性、解析、长度及配对结果，并保存带单位/分母的首拒绝计数；额外的独立检查计数 MUST 明确标注可能重叠，不当作可相加的流水线损失。

#### Scenario: 配对在不同阶段失败
- **WHEN** 一部分问题原本没有错误侧，另一部分问题存在错误侧但全部超长
- **THEN** 两类问题得到不同诊断，并能追溯到相应规则；旧版合并计数仅按历史语义展示

### Requirement: 对照构建使用固定来源池和题目分组
系统 MUST 在 A/B 策略应用之前固定来源内容、问题身份、阶段/训练评测分组及排序；修改配额或质量规则不能隐式改变问题所属分组。

#### Scenario: 对照组修改目标数量
- **WHEN** 相同来源池和 split 引用下的一组改变目标数量
- **THEN** 两组共享同一题目分组与评测隔离，数量差异来自筛选/选择，不来自重新分配题目

### Requirement: 本地预览有明确范围且不触发获取
系统 MUST 使用明确选择且可验证的本地原始数据或源缓存执行有界预览，记录样本选择方法、扫描数量、来源/策略摘要及不完整状态；预览 MUST NOT 自动下载数据或 tokenizer、调用外部模型，或从筛选后产物推算被删候选。

#### Scenario: 缺少原始输入或本地 tokenizer
- **WHEN** 用户仅有已筛选的数据集和聚合报告，或缺少声明的本地 tokenizer
- **THEN** 预览返回输入不可用及需要准备的资源，仍可浏览历史证据与编辑草稿，不发起网络获取

#### Scenario: 预览达到扫描预算
- **WHEN** 本地预览达到声明的行数或执行预算
- **THEN** 返回实际处理范围、停止原因与 partial 状态，不将该样本上的产出率或数量外推成全源结果

### Requirement: 小规模探索保持正式验收边界
系统 MUST 允许非空、满足所选探索规则和完整性要求的数据通过现有训练 CLI 进入探索流程，记录实际预算及不足告警；该执行 MUST NOT 因未达到 Mini 目标被表示为 Mini 已就绪，空数据不得启动训练。

#### Scenario: 使用少量 Preference 运行流程
- **WHEN** 探索计划仅有少量有效 pairs 且其他执行要求满足
- **THEN** 可以导出并执行对应 CLI 配置，保留实际 pair 数及结论范围警告，Mini readiness 仍独立显示不足

### Requirement: 策略输出复用现有数据与血缘契约
系统 MUST 为构建输出生成新数据版本、策略/来源/split 引用、处理报告、质量报告和数据构建 lineage，历史文件保持不变；相同内容/策略可复现身份，每次实际执行具有独立 run_id。

#### Scenario: 重建策略数据
- **WHEN** 用户使用相同来源、题目分组、策略和 tokenizer 重建
- **THEN** 输出内容和确定性身份一致，构建 run_id 不同，结果能通过既有 manifest 与完整 lineage 校验
