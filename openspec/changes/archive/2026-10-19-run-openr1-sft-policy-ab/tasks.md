# Tasks

## 1. 离线前置检查与实验配置

- [x] 1.1 核验 OpenR1 缓存 manifest 的 revision、行数和内容摘要，并确认本地 tokenizer 仓库/revision 与试验配置一致；保存可复查的预检记录，任何不匹配或需要联网补资源的情况均停止并记录阻塞原因。
- [x] 1.2 从已在本地且许可/版本可核验的 benchmark 材料准备专用、非空的污染索引；记录索引身份、摘要及许可/归属信息，并验证其可被来源档案读取。不得复用历史污染命中报告充当索引；若无合适本地材料则停止后续构建并记录需用户决策的资源缺口。
- [x] 1.3 在唯一试验目录创建来源档案及 A/B 策略配置；验证两策略除 `correctness`（A=`filter`、B=`report_only`）外完全相同，且两者均为 `usage=exploratory`，固定完整性/答案解析过滤、tokenizer、`max_length=1024`、split 配置与完整性防护。

## 2. 构建并验证数据对照

- [x] 2.1 在网络访问关闭或明确禁止联网回退的条件下，使用同一来源档案和策略构建 A/B 两组到新的独立目录；设置共同 `target_count=100000`、不设置 `max_scan_rows`，验证两份报告均观测到 93,733 行且 `stop_reason=source_exhausted`，否则停止并调查，不修改构建器。
- [x] 2.2 验证 A/B 的 `source_pool_id`、`split_snapshot_id` 和分组规则一致，数据 ID/哈希可追溯，train/holdout 无交叉污染；对照 `partial`、`stop_reason` 与 manifest 解释扫描完整性，并输出验证记录。
- [x] 2.3 生成并审阅数据质量对照报告：所有计数展示明确分母，区分正确/错误/未知标签，比较保留率、拒绝原因、答案可解析性、长度分布、来源/难度覆盖及污染结果；核验两臂 manifest、质量报告、处理报告和 lineage 完整，并确认两臂均未被标为正式 Mini 数据。

## 3. 预登记与有条件的模型对照

- [x] 3.1 根据两臂实际样本/token 数及本地 RTX 4060 训练配置判断训练可行性；若继续，先登记不可变的试验计划，记录单一变量、共同 parent 身份/哈希、resolved recipe、seed、共同实际预算、评测集身份/哈希、协议和指标，并验证登记可被比较工具接受。
- [x] 3.2 仅在两臂预算可安全匹配、评测资源本地可用且训练计划通过预登记校验时，从同一个已验证 parent 分别训练 A/B（优先使用可验证的 M1-CPT，否则两臂共同使用已验证 Base；禁止串联训练）；记录实际步数、样本/token 暴露、资源成本、失败和 checkpoint lineage。若任一门槛不满足，将模型效果标为 `NOT_EVALUATED` 或 `NOT_COMPARABLE`，不得为完成试验而下载或放宽条件。
- [x] 3.3 对两个 checkpoint 使用相同的固定 held-out 数据和评分协议完成评测；验证评测身份、配置和共同预算一致，并将小样本 smoke 指标仅作为描述性结果，不作泛化或因果提升结论。

## 4. 汇总、审计与项目记录

- [x] 4.2 确认历史 Mini 数据、原始缓存及冻结门槛未被修改；将本次试验状态和产物位置补入相应项目记录，明确 relaxed 策略结果仍为 exploratory，并验证文档引用的文件与实际产物一致。

## Workflow follow-up

- 归档前由维护者审阅数据来源许可/归属、质量报告、模型对照解释及未解决的阻塞项；未满足门槛时允许以数据阶段报告结束，不要求启动训练。
- 试验结束后按仓库 OpenSpec 流程归档本变更，并检查归档后的规格/状态。
