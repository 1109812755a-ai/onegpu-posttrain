# 变更提案

## Why

项目正从 Smoke 运行进入 Mini 和单变量实验，同一父模型将派生多组数据与并行模型。现有产物记录了运行细节，却无法稳定串起实际使用的数据、模型、配方、代码和评测；缺少轻量契约会让比较结果及只读前端出现错误归因。

## What Changes

- 为新构建的数据集增加带版本的文件级血缘；上游确有可靠标识时保留记录级来源。用数据构建 Run 连接输入、清洗转换、输出数据集与处理报告，用质量评估 Run 连接数据集与质量报告，不重新定义质量指标。
- **BREAKING**：统一身份语义：`experiment_id` 标识受控实验分组，`run_id` 唯一标识每次实际操作，`run_label` 仅是可重复的人类可读标签。新产物不再将 `run_id` 当配方标签，也不再引入 `execution_id`。
- 将数据构建、质量评估、训练、模型合并、评测建模为不同类型的 Run。训练 Run 记录输入模型、数据、配方／解析后配置、代码与实际 adapter；合并 Run 记录父模型、adapter 与实际合并模型。DPO、SimPO、GRPO 保留从同一 SFT 模型并行分叉的事实。
- 兼容直接传入普通 JSONL 的训练：记录可核实的文件证据并标记血缘不完整，不假造数据集 manifest；Mini／OVAT 正式验收要求完整 manifest 链路。
- 为新评测建立独立 Run 和评测产物，记录被评模型、评测数据和协议版本，支持从指标反查到模型、训练、数据处理及质量证据；提供本地 ID、引用、摘要和祖先关系校验，明确旧版／未知状态，不回写历史运行。
- 血缘只证明证据链可追溯，不凭清洗前后分数差断言因果。清洗效果归因由后续受控实验能力完成；本次仅保留可供其引用的稳定 ID。
- v1 保持本地轻量：不引入数据库、调度器、远程元数据服务、强制 OpenLineage／MLflow 依赖或全量历史回填。

## Capabilities

### New Capabilities

- `dataset-lineage`：新数据产物的稳定身份、数据构建／质量评估 Run、来源／转换祖先、质量证据与可用的记录级来源。
- `run-model-lineage`：统一 Run 身份、训练／合并与模型的祖先关系、失败语义及图完整性。
- `evaluation-lineage`：评测 Run 和结果到被评模型、数据、协议、指标及上游质量证据的追溯关系。

### Modified Capabilities

无；仓库尚无主干 OpenSpec 能力规格。

## Impact

涉及数据 manifest／构建和质量报告、训练与合并 CLI 输出、评测 CLI 输出、配方、只读前端、本地产物读取与校验，以及相应测试和中文文档。新产物采用新的 `run_id` 语义，相关读取器和配方需协同调整；历史产物保持原样并明确标为 `legacy`，不静默重解释。Mini／OVAT 结果被认定为完整可复现之前，应完成此能力；受控清洗效果报告不属于本变更。
