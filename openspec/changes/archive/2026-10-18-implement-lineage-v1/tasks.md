# 实施任务

## 1. 共享血缘契约

- [x] 1.1 增加带版本的 Dataset／QualityReport／Model／Evaluation 产物和五种 Run 类型的血缘 schema，明确可用、不可得、未计算状态；以单元测试验证接受 v1、识别旧产物且不重解释旧 `run_id`，并拒绝不支持的主版本。
- [x] 1.2 增加确定性摘要、每次实际操作唯一 `run_id` 生成与安全本地引用解析；以单元测试覆盖相同／变化的字节与配置、重复唯一 ID、目录顺序和越界路径。
- [x] 1.3 在血缘设计指南用中文说明 `experiment_id`、`run_label`、`run_id` 及产物 ID／摘要规则并给出示例；验证示例可被新 schema 解析。

## 2. 数据集祖先

- [x] 2.1 扩展新数据 manifest，并为真实数据构建生成 `data_build` Run，连接来源／父数据、转换／配置摘要、划分／计数单位、内容摘要、输出数据集与处理报告；以 OpenR1／FineMath 构建测试验证可重复性、变化输出及旧 manifest 加载。
- [x] 2.2 在规范化 OpenR1 输出中保留可用的 record／problem／generation 引用，偏好对包含两个父记录；缺少上游 ID 时标 `dataset_only`，并以完整／缺失来源的测试验证。
- [x] 2.3 为实际质量评估生成 `quality_assess` Run 与独立 QualityReport 身份，连接被评数据集、协议版本、检查结果及摘要；增加跨字段与报告摘要检查，用测试验证缺失／篡改报告、清洗前后两个真实版本，以及现有质量指标语义不变。

## 3. 训练与模型祖先

- [x] 3.1 新训练前解析模型与数据证据；将 recipe 标签迁移为 `run_label`，支持可选 `experiment_id`，为每次实际训练生成唯一 `run_id` 并阻止覆盖；以同标签重复执行、目标目录冲突和 manifest 不匹配测试验证。
- [x] 3.2 兼容无 manifest 的普通 JSONL：记录路径／内容摘要并标记不完整，不阻断训练；以 CLI 测试验证普通 JSONL 可运行，Mini／OVAT 完整血缘检查不通过。
- [x] 3.3 为 CPT／SFT 输出同目录 `lineage.json`，使其与 `run.json` 的 `run_id` 一致，记录解析后配置／代码证据、真实 adapter 与训练终态；dry-run 不声称实际 Run。以 PASS、dry-run、训练失败测试验证，并保持 CLI 退出码。
- [x] 3.4 将训练契约覆盖 DPO、SimPO 和两种 GRPO profile，正确处理 OOM／FAILED／部分输出；以同源父模型 ID／摘要和 GRPO 无 checkpoint OOM 测试验证。
- [x] 3.5 为合并建立独立 `merge` Run，记录父模型、adapter、合并模型及失败终态；以训练成功／合并失败和成功合并测试验证不同 `run_id` 与真实产物边界。
- [x] 3.6 用中文说明新旧运行、三层 ID 及 M0→M1→M2→M3 并行分支；验证文档示例可解析且旧 Smoke 运行作为 `legacy` 可读取。

## 4. 评测来源

- [x] 4.1 在新 `eval.json` 旁输出 `evaluation_lineage.json`，记录唯一评测 `run_id`、独立 `eval_id`、模型／数据／基准／协议／配置证据、状态及各指标分母；以完成、dry-run、失败／部分完成、未知修订测试验证。
- [x] 4.2 为缺失血缘及基准／协议不匹配增加比较提示，同时保留旧版分数展示；以同协议、不匹配和清洗前后描述性 delta 场景的评测／前端读取测试验证，确保不标为因果收益。
- [x] 4.3 用中文说明评测如何追到模型、训练／合并 Run、数据处理和质量报告，以及 `legacy`／`unavailable` 的含义；以 fixture 验证文档示例引用可解析。

## 5. 本地校验与只读消费

- [x] 5.1 增加针对指定根目录的只读血缘校验命令，区分重复产物 ID／`run_id`、本地悬空引用、环和摘要错误，以及外部证据不可得／普通 JSONL 不完整；以 CLI fixture 测试验证完整性错误返回非零码。
- [x] 5.2 前端目录复用共享血缘解析／校验，同时保留关联运行和旧版提示；以 UI API 测试验证可信关联、仅 ID 警告、格式错误及越界路径拒绝。
- [x] 5.3 用中文更新血缘、系统架构和数据处理效果设计文档的交叉引用，记录校验器用法与边界（完整性不等于质量或因果）；验证文档命令可在小型 fixture 上执行。

## 6. 端到端验收

- [x] 6.1 运行数据、训练、评测和前端相关测试及 `openspec validate implement-lineage-v1 --strict`；用小型 fixture 验证源数据 → 构建／清洗 → 数据集／处理报告 → 质量评估／报告 → 训练 → adapter → 合并 → 模型 → 评测／指标的完整与旧版状态。
- [x] 6.2 对照 Mini 验收清单检查输出产物，记录明确不可得的外部证据；验证普通 JSONL 未被误判为完整血缘、清洗前后描述性差异未被标为因果结论，且未引入数据库／服务或改写旧 Smoke 产物。
