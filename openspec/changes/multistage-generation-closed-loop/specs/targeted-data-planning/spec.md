# Spec Delta

## ADDED Requirements

### Requirement: 定向计划复用阶段数据准备能力
系统 MUST 允许 CPT、SFT、Preference 和 GRPO 定向计划通过与普通准备相同的阶段生成、质量、审核和登记能力创建数据；也 MUST 支持选择已登记数据或明确的导入、筛选、组合、可信派生路径，不要求定向补数必须调用模型。

#### Scenario: 从定向计划生成阶段数据
- **WHEN** 用户选择某阶段的定向计划并确认进入模型生成
- **THEN** 系统携带计划 ID/version、阶段、可用目标和兼容训练种子，复用该阶段的生成与登记流程，不自动调用 Provider 或启动训练

#### Scenario: 定向计划使用非模型生成来源
- **WHEN** 用户选择已登记数据集或导入、筛选、组合、可信派生作为补数来源
- **THEN** 系统记录实际来源与计划关系，不伪造模型生成运行；训练前仍需审查该来源的阶段、角色、质量和许可证据

### Requirement: 定向计划与执行和复测身份可追溯
系统 MUST 保留计划版本与实际数据准备、质量、dataset、训练、模型及评测身份关系，并明确区分未执行、阻断、失败和已完成；登记、训练和复测分别由用户确认。

#### Scenario: 生成 partial 数据用于训练
- **WHEN** 用户审核并登记非空有效的 partial 数据后发起训练
- **THEN** 计划引用真实 dataset ID/hash、生成与质量运行及实际数量，训练预检使用准确身份，不能把目标数量当作已完成数量

#### Scenario: 训练后进行复测
- **WHEN** 用户为定向训练后的已登记模型发起适用的阶段评测
- **THEN** 系统显示实际评测协议、分母与模型身份；缺基线、缺目标或协议不一致时标注未测/不可比较，不能声称提升或归因于生成数据

### Requirement: 定向输入与留出数据隔离
系统 MUST 在定向目标传递和数据准备时保留训练种子、诊断和最终 holdout 的角色及祖先，并仅使用被允许的数据内容；不得通过改变 ID 或进入共用生成器绕过隔离。

#### Scenario: 留出数据被选择为训练种子
- **WHEN** 定向计划尝试将诊断或最终 holdout 正文、答案或已知派生记录作为训练生成种子
- **THEN** 系统阻断该输入并解释原因；抽象场景信息与允许的训练来源可单独使用

### Requirement: 多次独立执行的证据可引用
系统 MUST 为多次数据准备、训练和评测分别保留稳定身份、输入与真实状态，并允许受控调用方只读引用这些证据；不得将一次计划、缺失记录或重复标签当作多次执行。

#### Scenario: 同一目标下进行多次独立试验
- **WHEN** 用户对同一目标分别执行多次准备、训练或评测
- **THEN** 每次真实执行保留独立身份及相关 plan/version、输入和产物，历史记录不覆盖；查询不会自动晋级模型或开启下一轮

### Requirement: 定向复测保留可比较性证据
系统 MUST 记录可得的被评模型 ID/hash、评测集 ID/hash、评测协议及配置、指标状态和实际分母，并保留训练、诊断和最终 holdout 的角色与祖先；证据不可得时不得推断一致性。

#### Scenario: 评测协议或身份无法核实
- **WHEN** 前后评测的模型、评测集摘要或协议缺失，或已知协议不一致
- **THEN** 系统保留真实缺项并将效果标记为未测或不可比较，不从指标值推断两次评测具有相同条件
