# 设计：多阶段普通生成与定向补数闭环

## Context

动机和范围见 proposal，行为契约见两份 delta spec。现有 `/api/synthetic/sft/*` 和 `SFTGenerationJobs` 承载 SFT 普通/定向生成，`targeted_capabilities.py` 仅将 SFT 声明为 Web 生成可用；`data/targeted_cpt.py`、`data/targeted_preference.py` 已有局部生成与检查，`data/grpo_seed.py` 是可信种子派生而不是模型调用。现有登记、组合数据集、Launcher、阶段评测和 lineage 应复用；不得以任务清单勾选推断真实 Provider/GPU 验收完成。

## Goals / Non-Goals

**Goals:**

- 以同一阶段生成/审核执行能力支撑普通入口与定向入口，且对用户暴露可信的各阶段可用性和任务状态。
- 在真实输入、预算、模型、候选、数据集、训练和评测身份之间建立可复查关联，兼容已有 SFT 记录。
- 以每阶段端到端交接、前端可操作性和可重复的离线测试为交付依据；真实调用/训练证据单独记录。

**Non-Goals:**

- 不承诺生成数量、事实正确性、模型效果改善，或未认证数据天然可训练。
- 不把所有阶段映射到同一 SFT schema，不把生成答案/自评直接升级为独立可信证据，不接受任意浏览器命令、代码、路径、reward 插件或密钥。
- 不为定向补数另造生成器/登记器，不删除、回写旧数据或改变已登记对象身份。
- 本变更仅为未来多轮分析保留证据和读取接口，不实现 RSI 轮次对象、自动晋级/回退、自动启动下一轮、停止策略或本地模型推理服务；现有阶段父模型规则不在此变更中放宽。

## Decisions

1. **一个阶段能力目录，两种入口。** 普通数据工作台以阶段、主题/可选训练种子和 Provider 开始；分析入口以诊断证据或用户目标创建定向计划后携带安全上下文进入同一数据工作台。能力响应按阶段与模式分别返回可执行状态、依赖及阻断，不仅检查代码文件存在。不同阶段有专属表单和协议。相比两套互不兼容的流程，共用入口减少重复登记和状态漂移。
2. **共用任务外壳，阶段适配器负责语义。** 复用 Provider transport、凭据、请求预算、ledger/cache、可恢复 job 与审核登记机制；以阶段和模式分派受控 adapter。候选、校验器及 canonical 格式独立，DPO/SimPO 共享 Preference 数据适配器。先映射兼容既有 SFT API/ID 与持久化状态，不破坏旧链接。相比复制 SFT job，统一外壳更利于错误脱敏和跨阶段一致性。
3. **证据驱动资格，而非数量驱动。** CPT 使用连续文本、领域覆盖、去重/污染及可得事实性证据；SFT 对没有独立 reference 的答案保留未验证状态；Preference 先生成同题候选，正确性排序由可信 reference/验证器证明，其他明确声明的偏好证据不能伪装为正确性证明；GRPO 的生成候选只有绑定当前可执行 reward 和可信 reference/验证构造后才有资格进入受控训练。纯模型自报可留作候选但不能升级信任。存在有效 partial 时按实际数量审核，零有效项不可登记为可训练集。
4. **复用不可变登记与精确交接。** 生成或非生成数据经阶段质量报告、人工审核与显式登记，生成数据的根来源或父 seed、模板/provider/profile、execution、候选和摘要进入 lineage；定向模式额外保留 plan ID/version。数据工作台交给现有 Launcher 时只带准确 dataset ID/阶段，不自动启动；多个来源先由现有 mixture 登记，训练和评测均各自重新预检并显式确认。诊断/holdout 和其已知祖先不能进入生成种子或训练集合。
5. **终态、成本和恢复以证据为准。** 每个 execution 落盘阶段、来源模式、不可变配置、进度、预算/已用、候选、拒绝/失败和 partial 状态；刷新只恢复观察，不重复调用。未确定是否受理的请求需显式处置，未知费用不记为零。Provider、API、日志和报告只暴露脱敏摘要；真实调用与 GPU 训练需用户分别确认。
6. **与既有变更明确分工。** 本变更拥有共用生成基础设施、各阶段普通/定向接入、用户端交接及由这些路径产生的独立验收证据。`targeted-data-stage-closure` 继续拥有其未完成 6.2 跨阶段计划历史/效果页和 6.4 既有范围集成验收；复用本变更产物与测试，不重复实现、不自动勾选原任务。实施前对照该变更和 `stage-training-evaluation-workbench` 的剩余任务，记录依赖，发现契约冲突先解决，不复制 Launcher/评测能力。
7. **生成模型身份可核实，不猜测。** 生成 execution 与可追溯来源记录 Provider profile、模型声明、可得 revision 及证据状态；当实际生成服务能提供足以核实的项目内登记模型身份时，额外绑定该模型的 ID、内容摘要和身份核验结果。仅凭同名、用户填写或无法证明服务加载的权重，不能声称关联已核验的本地模型；外部模型无法提供摘要/revision 时保持 unavailable/unknown。此项记录可用证据，不承诺接入或部署本地模型作为 Provider。
8. **单次执行独立且结果可机器读取。** 通过现有或扩展的受控只读接口按稳定身份查询生成任务、质量报告、数据集及评测状态，返回协议版本、真实输入/产物身份和摘要、终态、失败/partial 及证据缺失状态；不能依赖 UI 状态或解析自由文本日志，也不因读取而执行生成、训练或评测。多次独立执行保留各自身份，可由未来编排能力引用，但本期不创造虚构轮次或执行结果。
9. **保留数据与可比性证据。** 记录普通生成、定向生成、原始来源和派生/组合等实际来源及祖先，检查器/验证器的名称、版本、证据状态和真实覆盖/分母。训练/诊断/最终 holdout 角色及祖先不可被绕过；评测保留模型 ID/hash、数据集 ID/hash 或明确不可得、协议/配置、指标状态与真实分母；协议或证据不足时显示不可比较，不把缺失填成零。

## Risks / Trade-offs

- [阶段适配器与历史 SFT Job 不兼容] → 先建立旧任务/manifest/URL 回归，再逐阶段桥接；不迁移或覆盖历史对象。
- [GRPO 无可信 reference 或 Preference 无排序依据] → 保留草稿/候选与真实缺项，不降低训练 gate；提供可信来源和人工审核路径但不将人工声明冒充独立验证。
- [目标数据污染评测] → 训练/诊断/holdout 及祖先校验；未检查覆盖显示未测，不宣称无污染。
- [远程费用、凭据泄漏或长时间占用 GPU] → 预算与显式确认、脱敏、独立取消/状态、资源预检；真实验收只在用户确认时执行。
- [前后评测不可比或由生成数量误判效果] → 保留协议、实际分母、目标/保护指标，缺基线和不匹配显示未测/不可比；单臂结果仅为观察。
- [外部 Provider 的模型声明不等于项目模型产物] → 只有可证明实际服务加载身份的证据才绑定登记模型；缺少核验时保留声明和 unknown，禁止仅按名称猜测 ID/hash。

## Migration Plan

1. 先增加阶段 capability、共享 job/adapter 兼容层及旧 SFT 回归，不改变默认数据或历史身份。
2. 分阶段接入并在能力检查、交互与离线测试通过后开放相应入口；未就绪阶段保持明确阻断。
3. 复用已有定向计划、登记、训练和评测身份，记录交接和兼容性，更新中文指南与实际能力声明。
4. 回滚时关闭新增阶段入口并保留已生成的候选、登记数据、运行与 lineage；不删除或重写已有记录。真实 Provider/GPU 验收如未授权、受资源或许可证据阻断，记录为待验证而非通过。
