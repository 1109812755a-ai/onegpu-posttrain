# Proposal

## Why

模型体验目前按阶段和模型 ID 排列，选择项不显示训练时间或来源 Run；用户刚完成 SFT 后，难以辨认对应的可体验产物。为模型设置的用户显示名也能让多次实验更容易区分，但不能取代模型的不可变身份和血缘。

## What Changes

- 在模型体验目录中优先展示最近成功训练、且身份/血缘/权重校验通过的模型，显示训练阶段、训练完成时间、训练 Run 与模型 ID；默认选中最新合格模型，但不自动加载、不占用 GPU。
- 保留从 Run 详情“试用此模型”直达并预选确切模型的行为；该明确选择优先于最近模型默认值。
- 允许用户在成功 Run 的模型产物处填写、修改或清除用户显示名，并在模型选择项、体验结果与 Run 模型产物视图中一致展示。
- 将用户显示名作为工作区本地展示元数据，按不可变 `model_id` 关联；未命名时使用阶段、时间与 Run 短 ID 构造可读回退名称。
- 始终保留原始模型 ID、来源训练 Run、合并 Run 与摘要作为可见/可展开身份信息；显示名不得更改模型文件、模型 ID、摘要、Run 标签或 lineage。

## Capabilities

### New Capabilities

- `model-playground-discovery`: 最近可体验模型发现与按模型身份持久化的用户显示名。

### Modified Capabilities

无。Run/model 的不可变身份和血缘契约保持不变。

## Impact

涉及 `ModelPlaygroundCatalog` 与模型目录 API 的最近训练信息、工作区本地模型显示名元数据读写、模型体验页的最近模型卡片/选择器/结果呈现，以及成功 Run 模型产物中的命名入口。需要覆盖保存与清除别名、最近模型排序、Run 深链优先级、旧记录回退显示、模型身份不变、窄屏与键盘交互的测试。不会修改训练、合并、推理、模型文件或正式 Run/lineage 数据。
