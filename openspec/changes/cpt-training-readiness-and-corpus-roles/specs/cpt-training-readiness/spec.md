# Spec Delta

## Purpose

为 CPT 阶段提供可追溯、角色隔离的数据输入和明确可操作的训练就绪反馈，使用户能够修复可信构建产物并识别本地运行环境阻断，同时避免把未经确认的数据或远程依赖误判为可训练。

## ADDED Requirements

### Requirement: CPT 构建显式标记训练与留出角色
所有项目支持的 CPT 构建器 MUST 为每条规范记录写入有效的 `metadata.data_role`，并在登记证据中报告各角色数量；训练与评测入口 MUST 只消费与其用途匹配的角色。

#### Scenario: FineMath 生成训练与留出划分
- **WHEN** FineMath 构建器输出 CPT 训练集和留出集
- **THEN** 训练记录标记为 `train_seed`，留出记录标记为 `final_holdout`，报告中的角色计数与实际 canonical 行数一致

#### Scenario: 不允许角色混入训练数据
- **WHEN** CPT 训练预检读取缺少角色、角色值无效或非 `train_seed` 的记录
- **THEN** 预检阻断启动，并报告角色/schema 错误及对应计数，不推断缺失角色

### Requirement: 历史 CPT 数据修复必须有可信来源
系统 MUST 仅对可验证为受支持项目构建协议产物的历史 CPT 数据提供显式升级/重建；任意上传或来源不明的数据 MUST 保持阻断，直至用户通过受支持的数据准备流程明确声明并验证角色。

#### Scenario: 可信旧构建可升级
- **WHEN** 用户请求升级具有有效 manifest、处理报告、canonical 摘要及受支持构建协议的旧数据集
- **THEN** 系统先展示可验证的角色来源和升级预览，随后生成新 canonical 内容、新数据集 ID、哈希、处理报告和血缘，旧产物保持不变

#### Scenario: 上传数据缺少角色
- **WHEN** 用户上传或登记的 CPT 数据缺少逐条角色声明，且没有受信任的构建证据
- **THEN** 系统不按文件名、manifest 阶段或行位置自动补充角色，并说明如何重新导入或显式标注

### Requirement: CPT 预检按类别解释运行阻断
CPT 预检 MUST 分别报告数据及登记证据、`swift` 命令、固定 Base 模型本地配置/权重和 GPU 可用状态，并为每个失败项提供对应的修复指引；预检 MUST NOT 自动安装依赖或联网下载模型。

#### Scenario: 数据角色与本地运行环境均有问题
- **WHEN** CPT 数据角色无效且项目运行环境缺少训练命令或本地模型权重
- **THEN** 预检同时给出各自独立的阻断项，不以一个泛化错误覆盖其余原因，并保持 `execution_started` 为 false

#### Scenario: 未安装训练依赖或模型未缓存
- **WHEN** `swift` 命令不可用或 pinned Base 模型配置/权重不在本地
- **THEN** 预检明确指出需要在项目 Python 环境安装受支持的训练依赖或准备匹配的本地模型文件，且不发起安装、下载或训练

#### Scenario: 所有硬性条件满足但有来源提醒
- **WHEN** 数据角色、登记证据、训练命令及本地模型文件均通过，但质量或许可状态仍待确认
- **THEN** 预检保留独立提醒并按既有确认策略处理，不把提醒伪装成技术阻断或质量认证
