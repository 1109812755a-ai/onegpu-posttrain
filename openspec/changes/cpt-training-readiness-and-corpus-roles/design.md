# 设计

## 上下文

参见 `proposal.md`。现有 FineMath 生成器分别输出 `cpt` 和 `cpt_holdout`，但记录 metadata 没有 `data_role`；CPT 校验器已 fail-closed，因而这些旧 canonical 行不能进入训练。CPT adapter 将数据与父模型核验包在同一异常路径中，数据失败时会丢失模型可用性细节；其 `swift` 探测也没有复用共享的子进程 PATH 探测逻辑。项目已有 `DatasetLineage`、manifest 摘要校验、登记数据集 adapter 和受控 CPT CLI。

## 目标 / 非目标

**目标：**
- 让新构建 CPT 训练/留出记录符合已有角色隔离契约，并把协议和角色计数写入可核验构建证据。
- 为历史上由可信构建器生成但缺角色的 CPT 数据提供显式、可审计且不覆盖原件的修复流程。
- 让预检准确列出各个独立阻断和修复动作，保持只读、离线和未启动语义。

**非目标：**
- 不将任意上传的 CPT JSONL 自动变成可训练数据，也不从内容、行序、文件名或未经核验的阶段标签猜角色。
- 不在预检中自动安装 ms-swift、下载 Base 模型或启动训练；不把质量/许可提醒解释为质量认证。
- 不在本次提案中承诺真实 GPU 上所有 CPT recipe 已完成训练验收。

## 决策

1. **角色在构建时写入，不在消费时猜测。** FineMath 的训练输出写 `train_seed`，留出输出写 `final_holdout`；其他受支持 CPT builder 也必须声明角色协议。角色分布进入 processing report/manifest，并在登记/预检时与 canonical 行数核对。优于只放宽 validator，因为放宽会让含混的用户上传数据绕过训练隔离。

2. **历史修复采用“验证来源后新建派生数据集”。** 仅接受 manifest、canonical SHA-256、处理报告摘要及支持的 builder/protocol 共同证明来源的旧项目产物。升级命令先提供 dry-run 预览，再把显式角色写入新 canonical 内容并登记新 ID、摘要、处理报告和 `DatasetLineage.parents`/transform 证据；旧路径只读保留。来源不够可信时拒绝升级，改走显式重新导入/标注。优于原地补字段，因为哈希、登记身份和历史训练复现都不能被静默改变。

3. **预检各自执行与汇报独立检查。** 拆分 CPT dataset/evidence validation、pinned Base 本地配置/权重验证、当前 Python 对应脚本目录中的 `swift` 探测、GPU 快照。一个失败不短路其余检查；响应保留稳定 check ID、状态、细节和可操作指引。模型检查结果不再由“整个 CPT 预检是否成功”推断。`swift` 探测复用 `console_command_available` 以匹配实际 child PATH。训练启动仍重复校验所有关键身份和摘要，避免预检与启动间数据变更。

4. **依赖准备走明确的本地路径。** `train` extra 已固定 ms-swift 版本，预检输出项目环境安装提示；模型提示显示 recipe 固定 repo/revision，建议用户通过已有缓存或显式本地模型登记准备文件。预检永不调用包管理器或模型网络下载。优于预检自动修复，以免改变用户环境、造成非预期网络访问或带来不可控版本。

## 风险 / 权衡

- [角色标记变更会改变 canonical 哈希和数据集 ID] → 新建版本并保存来源/处理血缘，要求用户在训练器中选择新 ID，保留旧 ID 供追溯。
- [角色字段的兼容性扩大到其他 CPT builder] → 建立 builder 清单和契约测试，任何受支持 builder 都必须按 split 标角色；上传注册的严格规则不放宽。
- [本地模型权重格式或分片布局多样] → 复用现有模型可用性检查规则并在预检展示检查内容，不以仅有 `config.json` 判为就绪。
- [系统有脚本但当前进程 PATH 异常] → 使用项目 Python 的 scripts/bin 路径进行可执行性检查，并覆盖 Windows 虚拟环境测试。

## 迁移计划

1. 先改 builder 和新数据契约测试，确认新输出带角色且角色计数与文件一致。
2. 增加可信旧构建 dry-run 与显式派生登记；验证旧 artifact 的文件摘要和字节不变。
3. 更新 CPT 预检/API/UI 诊断和修复指引，不改变数据合格条件，不执行环境修改。
4. 用测试夹具覆盖角色缺失/冲突、可信/不可信旧产物、缺 swift、缺 Base 配置/权重及多个阻断并存；完整后端测试通过后再由用户在已准备好模型与依赖的真实本机环境尝试训练。

回滚时可停止使用新的修复命令和 UI 诊断，并继续读取旧数据；新注册的数据集保持独立且可追溯，不覆盖任何旧 artifact。
