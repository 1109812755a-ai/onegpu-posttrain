# 提案：修复 CPT 数据角色与训练就绪链路

## 为什么

当前 CPT 训练入口会拒绝项目构建的 FineMath 数据：记录缺少预检要求的 `metadata.data_role`。即使修复数据，项目虚拟环境中的 `swift` 命令和配方指定的本地 Base 模型权重也可能缺失，用户目前难以从预检中区分这些独立原因，因而无法判断怎样才能真正启动训练。

## 变更内容

- 让 CPT 数据构建器为训练与留出记录写入明确、相互隔离的角色，并在处理报告/manifest 中记录角色协议及计数。
- 为可信旧构建产物提供只读检查与显式、可追溯的重建/升级路径；创建新数据集身份和血缘，不原地改写旧 JSONL、manifest 或报告。来源不明的上传数据不得自动补角色。
- 将 CPT 预检结果拆分呈现数据角色与 schema、登记证据、ms-swift 可执行环境、本地 Base 配置/权重及 GPU 状态，并给出对应的本地修复指引；预检仍不自动安装依赖或下载模型。
- 通过单元和 API/UI 测试覆盖新建、兼容边界、阻断诊断和血缘完整性。

## 能力

### 新增能力
- `cpt-training-readiness`：CPT 训练数据角色隔离、可信历史产物修复，以及训练环境就绪诊断。

### 修改能力
- `dataset-lineage`：修复/重建必须生成新身份并保留旧数据集、输入摘要、处理协议和来源关系。

## 影响

- 涉及 `data/finemath.py`、`data/build.py`、CPT canonical 校验及登记/预检适配器、训练依赖探测、CPT 数据构建命令、相关测试与训练工作台诊断展示。
- CPT 训练保持 fail-closed：没有明确 `train_seed` 角色、登记证据、ms-swift 命令和固定 Base 模型的本地配置/权重时，不允许启动。
- 不改变通用用户上传数据的角色声明策略；不自动联网、不自动 pip 安装、不声称真实 GPU 训练已通过。
