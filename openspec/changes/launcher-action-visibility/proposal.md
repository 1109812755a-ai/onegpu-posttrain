# Proposal

## Why

训练与评测的关键按钮不够醒目，且用户难以区分预检与真正启动；条件未满足时也不清楚下一步要补什么。当前页面的主操作缺少统一的高对比样式，长配置页还会把确认启动动作推到视野之外。

## What Changes

- 为训练配置检查、确认启动训练、阶段评测预检和确认启动评测建立一致且清晰的主操作层级。
- 明确呈现“配置/选择 -> 预检 -> 确认启动”的当前步骤，并在预检通过后突出唯一的下一项主操作。
- 在按钮不可用时就近说明缺少的父模型、数据、协议或运行条件；在长页面中保持关键操作容易找到。
- 确保活动任务状态下不显示可重复启动的误导性操作，并提供查看运行入口。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `web-workspace-ux`: 补充训练与阶段评测主操作的可发现性、阶段反馈和禁用原因要求。

## Impact

- 影响本地训练与评测工作台的前端按钮样式、操作区布局、预检/启动状态文案及交互测试。
- 不改变训练/评测 API、任务生命周期、数据/模型身份、预检规则或 GPU 串行约束。
