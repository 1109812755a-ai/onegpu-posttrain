# Data Policy Comparison Specification

## Purpose

让用户事先登记数据策略对照的问题、变量与控制条件，并把每组的数据变化关联到实际训练模型和评测证据。比较结果同时呈现质量、覆盖、预算、成本与不确定性，使数据规则和后续定向合成数据的效果可以复查，而不会从筛选数字直接推断模型提升。

## Requirements

### Requirement: 策略实验在执行前登记变量与控制条件
系统 MUST 为实验保存 experiment_id、问题、类型、来源池/split、A/B 策略、parent 模型、训练配置、预算单位/值、seed、评测数据与协议，以及主指标和保护指标；每个实际操作使用独立 run_id。

#### Scenario: 建立单变量规则对照
- **WHEN** 用户登记受控质量消融并修改一项筛选规则
- **THEN** 实验记录独立变量及两组完整配置，检查其他声明控制条件，未生成运行前结果保持未评估

### Requirement: 流水线效果与单变量消融有不同解释
系统 MUST 区分 pipeline_effect 与 controlled_quality_ablation；后者需要匹配声明的训练预算和控制条件，前者保留真实数据量与组成变化且不将差异归因于单条规则。

#### Scenario: 筛选同时减少数据量并改变难度覆盖
- **WHEN** 两组训练数据量或覆盖随策略变化且未满足匹配预算要求
- **THEN** 报告这些差异，可展示流水线效果；不能自动给出某条过滤规则导致能力提升的结论

#### Scenario: 单变量模式改变多个设置
- **WHEN** 受控实验的两组同时改变正确性策略和长度上限
- **THEN** 校验指出多个变量，要求修订实验定义或明确改为流水线效果，不能静默接受为单变量实验

### Requirement: 数据差异与模型结果通过身份关联
系统 MUST 按精确数据/策略摘要和 run/model/evaluation 身份关联每个实验组，报告实际数量、质量及覆盖变化，并在有真实评测时报告主指标、保护指标、资源成本与 delta。

#### Scenario: 文件名相似但 lineage 不匹配
- **WHEN** 某训练 run 没有消费该实验组登记的数据版本或 parent
- **THEN** 该 run 不能仅凭目录名、阶段或标签被关联为该组的结果，报告不匹配原因

### Requirement: 比较进行评测和预算兼容性检查
系统 MUST 检查评测集合/角色、评分协议、分母、parent、recipe、seed 与预算是否满足已登记约束；不满足时保留原始结果并标为 NOT_COMPARABLE，不能生成可比排名。

#### Scenario: 一组换用更容易的评测集
- **WHEN** 两组评测数据摘要或协议不同
- **THEN** 展示各自指标及差异原因，不将分数相减后解释为可比收益

### Requirement: 未执行失败和小样本保持可见
系统 MUST 区分未评估、运行失败、OOM、部分结果与可比结果；所有比例显示分母，单 seed/少量评测须注明结论范围，缺失指标不能补成零。

#### Scenario: 尚未训练或只有一条偏好评测
- **WHEN** 实验只有数据预览，或实际评测样本极少
- **THEN** 前者仅报告数据差异和模型效果未评估，后者显示真实分母及局限，不宣称策略稳定优于另一策略

### Requirement: 比较产物可导出且不回写来源
系统 MUST 以版本化实验登记与结果报告保存策略、数据、运行、模型和评测引用及摘要，支持 JSON/Markdown 导出；重新汇总结果生成新报告，不改写历史数据/评测文件。

#### Scenario: 后续补齐一个实验组
- **WHEN** 用户登记已有训练与评测产物并重新生成比较报告
- **THEN** 新报告引用补齐的结果及校验状态，旧报告仍可检查，输入 artifact 内容不变
