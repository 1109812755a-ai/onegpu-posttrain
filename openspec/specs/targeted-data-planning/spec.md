# Targeted Data Planning Specification

## Purpose

把模型诊断评测中的场景缺口转为可复查的定向数据计划，记录场景定义、样本证据、目标、训练来源和后续复测协议。该能力使单卡实验室能够评估定向补数是否改变目标能力和其他能力，同时防止把评测题的复述、指标缺失或生成数量当作能力提升。

## Requirements

### Requirement: 场景诊断基于可追溯评测证据
系统 MUST 根据版本化场景定义和真实题目结果/标签汇总指标，记录 eval/model/dataset/protocol 身份、分子分母、覆盖及解析/评分失败；无场景证据、空集合和不支持项 MUST 显示不可用，不能由总分推算。

#### Scenario: 评测报告只有总准确率
- **WHEN** 输入仅有总分而无题目结果或场景映射
- **THEN** 可引用总分，但场景指标保持未评估并指出缺少的证据，不自动编造薄弱场景列表

#### Scenario: 场景样本不足
- **WHEN** 场景可用样本数低于预先登记的诊断样本要求
- **THEN** 报告真实分母与证据不足，不把随机波动直接解释为已确认能力缺口

### Requirement: 补数计划在生成前固定问题与预算
系统 MUST 保存 plan_id/version、场景定义、诊断引用、目标和阈值来源、种子数据、生成阶段/策略、调用及数据预算、起点模型、复测/保护指标和停止条件；修改计划生成新版本，不回写历史目标。

#### Scenario: 针对代数场景建立计划
- **WHEN** 用户选择具备可用诊断证据的代数场景并登记期望目标
- **THEN** 计划引用该诊断和隔离训练种子，固定生成/训练/评测控制条件，执行前显示待执行而非预计提升

### Requirement: 诊断与最终评测角色明确
系统 MUST 区分 train_seed、diagnostic_dev 与 final_holdout，生成输入只使用允许的训练种子和抽象场景描述；评测题、答案和其派生改写不能进入训练，最终留出评测不能作为反复定向调参的数据源。

#### Scenario: 用户选择最终留出题作为生成种子
- **WHEN** 计划引用 final_holdout 或诊断题正文/答案作为训练生成输入
- **THEN** 校验拒绝并指出角色冲突；可以改用独立训练题和抽象技能描述，但不能通过改写或换 ID 绕过祖先隔离

#### Scenario: 已反复使用留出集选择数据策略
- **WHEN** 输入评测集已被用于定向策略选择
- **THEN** 计划将该用途记录为 diagnostic_dev，不能继续声称其是未用于调优的最终留出集；正式最终评估需要另行固定的独立数据

### Requirement: 定向种子与候选保持训练祖先关系
系统 MUST 为种子记录训练来源、问题/场景身份和分组，并对生成候选执行精确/近似污染检查及祖先隔离，记录方法和局限；修改候选文本不能消除原有评测祖先。

#### Scenario: 训练候选与评测问题重复
- **WHEN** 新候选命中已登记诊断或最终评测问题的 ID、祖先或污染检查
- **THEN** 候选不能进入训练输出，报告拒绝原因及检查覆盖；未执行检查不能显示零污染

### Requirement: 复测区分进展观察和受控补数实验
系统 MUST 允许 before_after_pipeline 和 matched_budget_ab 两类计划；前者报告追加训练前后在相同评测上的变化及训练预算变化，后者复用单变量对照要求并固定共同模型起点与预算。

#### Scenario: 仅运行一次定向追加训练
- **WHEN** 新模型从诊断模型追加训练后接受相同协议复测
- **THEN** 报告作为前后流水线进展，展示数据及额外训练成本，不把变化单独归因于合成数据质量

#### Scenario: 研究定向数据是否优于普通补数
- **WHEN** 用户选择匹配预算 A/B
- **THEN** 两组从同一模型出发，登记普通补数/定向补数的唯一策略差异并匹配所声明的训练预算，使用同一评测与保护指标

### Requirement: 补数结果同时报告目标指标与退化
系统 MUST 按预登记目标、评测协议、分母和保护指标汇总诊断/复测结果，保留目标未达、无收益、退化、失败及缺结果；生成数量、训练 loss 或 reward 上升不能代替能力评测。

#### Scenario: 目标场景提高但其他能力下降
- **WHEN** 目标场景指标改善而预登记保护指标超出允许退化范围
- **THEN** 两种变化同时可见，计划不能自动标记为整体成功，也不自动启动下一轮生成或训练

### Requirement: 前端能查看和准备定向计划
界面 MUST 在已有 Data/比较流程内展示场景缺口、证据状态、生成配置摘要、预算、验证产出和复测结果；计划编辑/导出遵循已有本地编辑模式，保存和 dry-run 不进行远程调用。

#### Scenario: 用户保存生成计划但未执行
- **WHEN** 用户选择场景、模型配置和提示词并导出计划
- **THEN** 显示凭据引用是否就绪和后续 CLI 操作，不泄露密钥，不产生调用费用或伪造已生成/已提升状态
