# 前端页面规格

**范围：** 页面按“数据、训练与评测、实验 Runs、分析与改进”四个主模块组织。规格强调可复现的对象身份、真实状态和用户下一步；尚未实现的阶段能力必须标为规划或 blocker，不得在界面中伪装成可运行。

数据处理轨迹与数据到模型的效果关系遵循[数据处理与模型效果详细设计](../DATA_PROCESSING_EFFECT_DESIGN_zh.md)。

## 1. 数据

### 数据集目录与来源

- 展示已登记数据集的名称、阶段、来源、数量/单位、质量状态、许可状态和可用操作；支持按阶段和来源筛选。
- 数据来源和训练阶段是独立维度；来源/许可未知仍可登记，但状态不能被格式校验自动升级。
- 本地导入必须由用户选择阶段并校验该阶段 canonical schema；模型生成只开放真实实现的阶段和模式。
- 可按需预览本地导入、开源构建和模型生成样本；必须校验记录身份与摘要，仅返回有界字段和样本数。

### 数据集详情

同一个 `dataset_id` 在任意入口打开同一版本详情，至少包括：

- **版本与来源：** 阶段、来源/revision、许可声明、样本单位与数量、内容摘要；摘要与路径默认折叠。
- **样本：** 有界样本预览；预览成功只证明读取内容与登记摘要一致，不代表语义质量或许可通过。
- **质量：** 按协议展示指标、单位、分子/分母、状态、局限和报告引用；缺失值不得用 0 代替，不计算无依据的综合质量分。
- **处理血缘：** 按顺序展示来源到最终数据集的处理步骤、规则版本、输入/输出计数、拒绝原因和报告引用。缺少报告时说明未提供，不猜测。
- **模型/Run 血缘：** 展示明确登记的 parent dataset、使用该数据集的 Run、产出模型和评测链接；只有真实 lineage 引用才建立关系。

目录中的样本预览、质量与血缘可按需读取；单个详情接口失败应留在该详情区并提供重试，不能隐藏其他数据集或 Runs。

### 处理与规则

- 处理与质量视图展示已有数据构建流程、质量、分布、污染和重叠报告；计数须标明 raw rows、documents、examples、pairs、prompts 或 tokens。
- 规则编辑与同源样本筛选预览归数据模块。规则方案和实验身份稳定，执行结果可从分析模块回链。
- 模型/recipe 相关校准与独立的数据集质量报告分开展示。

## 2. 训练与评测

- 训练入口按 CPT、SFT、DPO、SimPO、GRPO 列出已实现且已批准的阶段配置；阶段使用兼容的登记数据集、父模型规则和固定 profile。
- 选择数据后先预检，展示 dataset ID/摘要、来源许可与质量证据、父模型、profile、资源提示和 blocker；必须显式确认后启动。
- 不接受任意 shell、模型/数据路径或未批准超参数。一次只允许一个本机 GPU 活动任务。
- 训练阶段和父模型关系明确显示；缺少 parent 时由用户先完成上游工作流，不自动串跑。
- 成功训练 Run 的模型身份核验后，才提供适用评测的独立预检和启动；评测不覆盖训练终态，不复用训练数据冒充泛化结果。
- 未实现、未测量、不可运行、部分完成和失败应显示实际状态与原因。

## 3. 实验 Runs

- 列表支持按 `run_id`、阶段、算法、状态、时间及可用资源信息筛选；缺失时间/显存显示为未知，不当作 0。
- 同一 `run_id` 从 Launcher、数据详情或分析页面打开相同 Run 详情。
- Run 详情展示真实状态、实时或最终日志、训练配置摘要、父模型、实际 dataset ID/hash、模型产物、评测引用与 lineage。
- 评测是独立 Run；评测失败不改变训练成功状态。失败、OOM、服务中断或合并失败时不得伪造模型产物，也不得开放依赖缺失模型的评测操作。
- 高级配置、路径、hash 和原始 JSON 按需展开；日志区域有界并可独立滚动。

## 4. 分析与改进

- **阶段比较：** 只有 benchmark 版本、样本范围、解码/解析协议与分母相同才计算 delta；其余展示兼容性差异，不能默认评出赢家。
- **策略效果：** 在独立只读视图展示真实执行的 baseline/对照规则、数据质量变化和模型评测 delta；报告身份可通过 `report_id` 深链定位。规则编辑和数据筛选预览仍留在数据模块；如没有受控评测则标为未测量。
- **薄弱场景：** 显示诊断指标含义、样本分母、来源模型/Run/evaluation 和场景身份；用户选择补充数据时将上下文交给数据模块。
- 定向数据必须遵循 train seed 与最终 holdout 隔离，不能将 holdout 样本发送给生成 provider 或用作训练数据。

## 通用交互要求

- 四个主模块职责稳定；功能放在其负责的模块内，不将同一个对象拆成多个互不相关的页面副本。
- 页面加载、空结果、错误、部分数据和未支持状态分别呈现；提供就近恢复动作。数据目录与来源能力独立加载，目录问题显示部分可读，不误报整个 API 离线。
- 指标提供中文含义、单位、分子/分母、协议和证据来源；状态不能只靠颜色表达。
- 草稿、预检 token 和已启动任务身份分开；普通 SFT 草稿保存在本机，预检确认不跨刷新复用，execution/run 引用用于读取服务端真实状态。切换页面、普通生成方式或刷新不应丢失活动任务，也不得自动重试。
- 活动任务横条在各模块独立显示正在运行的生成、训练或评测，并提供返回任务/Run 的入口；单个可选任务接口失败不得隐藏其他任务。
- 跨模块动作携带 `dataset_id`、`run_id`、`model_id`、`eval_id` 或明确场景身份，尽量保留返回路径，不要求复制内部 ID。
- 桌面、390 CSS 像素窄屏和键盘操作均可用；窄屏采用单列或横向二级导航，长日志/表格在自身区域滚动。
- 主操作突出当前状态下唯一合理的下一步；高级原始信息按需展开。

## 当前已实现范围

- 数据集工作台支持来源能力查看、本地 canonical JSONL 登记、跨来源有界样本预览、质量摘要及处理报告/关联 Run 查看。
- 规则编辑与薄弱场景诊断保留在数据、分析各自入口；阶段比较、已执行策略效果和薄弱场景都属于分析模块。普通和定向 SFT 生成在数据模块共用预览、人工审核和登记流程，定向场景与来源评测身份随上下文交接。
- 普通 SFT 草稿、生成 execution 引用及 Launcher 最新 Run 可在刷新后恢复；全局活动任务横条可返回当前生成、训练或评测。
- 当前 Mini 只读切片：固定 Mini SFT profile 可真实启动；CPT、DPO、SimPO、GRPO 阶段工作台提供批准 profile、数据/父模型选择与只读 preflight，不启动训练。成功且 lineage 合法的阶段训练 Run 可在 Runs 详情发起适用的独立评测。
