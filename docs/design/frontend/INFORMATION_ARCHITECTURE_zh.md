# 前端信息架构

## 产品目标

OneGPU-PostTrain 是面向单张消费级 GPU 的可复现后训练实验室。前端按用户要完成的工作组织页面，让用户从数据来源和质量证据进入训练，再追踪 Run、模型、评测和数据血缘。首期保持本地优先、单活动 GPU 任务和受控配方。

## 主导航

工作区固定为四个主入口；每个入口只聚合同一类任务，二级视图承接具体操作。

| 主模块 | 用户任务 | 二级视图 | 主要对象与下一步 |
|---|---|---|---|
| 数据 | 获取、检查和登记训练数据 | 数据集；处理与质量；规则对照 | 数据来源、样本、质量报告、血缘、登记数据集 ID；可把已登记数据交给训练 |
| 训练与评测 | 选择阶段和数据，显式启动训练 | 训练与评测 | CPT、SFT、DPO、SimPO、GRPO 的阶段配置和预检；启动后打开对应 Run |
| 实验 Runs | 观察任务并追溯真实产物 | 运行记录 | 训练/生成/评测状态、日志、指标、模型与数据 lineage；成功模型可显式启动适用评测 |
| 分析与改进 | 理解效果并决定下一轮实验 | 阶段比较；策略效果；薄弱场景 | 可比评测矩阵、已执行策略效果、薄弱场景；定向补数携带来源评测/模型/Run 上下文进入数据获取 |

“概览”和“对齐分析”在没有完整可操作页面前不作为主导航入口。阶段能力不可用时，在阶段页展示具体 blocker，不显示误导性的可用状态。

## 端到端对象流

```text
数据来源 / 本地导入 / 模型生成
               ↓
      处理、质量评估与登记
               ↓ dataset_id
       阶段训练与显式预检
               ↓ run_id
         Runs 详情与模型
               ↓ 独立 evaluation run
          分析与下一轮改进
               └──── 定向目标回到数据获取
```

训练阶段和数据来源是两个维度。数据模块负责生成、审核、质检、登记和数据血缘；训练模块消费明确的已登记 dataset ID；Runs 是执行状态和模型产物的事实来源；分析模块读取真实评测证据。阶段间父模型关系通过模型 lineage 展示，不自动串跑上游训练。

## 页面职责与边界

- **数据集：** 浏览已登记数据、按阶段/来源筛选、预览样本和查看统一数据集详情。详情承接样本、来源许可、质量报告、处理证据、数据 lineage 和关联 Run。
- **处理与质量：** 浏览已有处理报告、质量与分布；数据规则编辑和预览也归此模块。格式有效、语义质量、许可状态和训练 readiness 分开展示。
- **规则对照：** 配置规则并预览同源数据的筛选差异；已执行实验的模型效果报告归“分析与改进”，通过同一策略/实验身份互链。
- **训练与评测：** 展示阶段、批准 profile、兼容 dataset ID、父模型和 blocker；每次训练需显式预检和确认。第一版只开放实际实现且可验证的阶段能力。
- **运行记录：** 列表和同一 Run 详情展示状态、日志、配置摘要、训练数据/父模型、产物、评测及 lineage。评测是独立执行，不覆盖训练终态。
- **阶段比较：** 仅对协议、数据版本、样本分母和覆盖相匹配的结果计算差值；其他指标分别展示并说明不可比原因。
- **策略效果：** 只读查看实际保存的效果报告；报告身份、数据质量变化、兼容性限制和模型评测共处一处。规则编辑/数据预览的返回入口仍在数据模块。
- **薄弱场景：** 诊断来源评测、模型、Run 和目标；“补充数据”将这些对象身份传递到数据生成流程，生成/审核/登记仍使用数据模块的流程。

普通生成与定向生成共享适用的执行、质检、审核和登记操作，但保留各自必要的输入字段。普通生成不要求用户手填内部方案 ID。活动任务的身份与状态独立于当前表单草稿。

## URL 与浏览器历史

兼容旧 `page` 参数，页面保持现有二级视图标识：

| 旧链接 | 新模块位置 |
|---|---|
| `page=workbench` 或无筛选的根路径 | 数据 / 数据集 |
| 无 `page` 且含 `scope/build/stage/tab` 等报告上下文，或 `page=data` | 数据 / 处理与质量，并恢复旧筛选 |
| `page=policies` | 数据 / 规则对照 |
| `page=launcher` | 训练与评测 |
| `page=runs&run=...` | 实验 Runs / 对应运行 |
| `page=comparison&matrix=...` | 分析与改进 / 对应阶段比较 |
| `page=policy-effects&report_id=...` | 分析与改进 / 指定策略效果报告 |
| `page=targeted` | 分析与改进 / 薄弱场景 |

模块只写入自身拥有的 URL 状态：数据视图管理数据筛选，训练只接收适用阶段和 dataset ID，Runs 管理运行身份/筛选，分析管理矩阵或明确的改进上下文。跨模块导航不携带无关的 build、tab 或搜索条件。浏览器前进/后退恢复目标视图及其对象身份。

## 对象身份与可追溯性

- **Dataset：** `dataset_id`、阶段、来源/revision、内容摘要、质量/许可证据和 parent dataset lineage。
- **Training Run：** `run_id`、阶段/profile、实际 dataset ID/hash、parent model ID/hash、配置摘要、状态及产物引用。
- **Model：** model ID、产生它的 Run、父模型关系、adapter/merged 类型和可验证摘要。
- **Evaluation Run：** 独立执行身份、目标模型、评测数据/benchmark、协议、分母、指标状态和训练 Run 引用。
- **数据改进实验：** 场景、来源评测/模型/Run、规则或生成方案版本，以及产出 dataset ID；不把评测 holdout 样本用作训练生成输入。

用户界面默认使用易读名称、阶段、样本数和状态。精确 ID、hash、原始配置和路径按需展开，不要求用户复制粘贴才能完成跨模块操作。

## 状态与交互原则

- 每个模块独立显示加载中、空数据、错误、部分结果和未支持状态；单个目录接口失败不能隐藏仍可访问的 Runs。
- 指标显示中文含义、单位、分母、协议与状态。未测量、不可用、失败和零值不能混为一谈。
- 草稿改变会使对应预检失效；已启动 execution/run 不随草稿重置、视图切换或刷新而丢失，也不会自动重启。
- 主操作明确且按当前工作流状态排序；浏览/导航不自动触发数据生成、训练或评测。
- 支持桌面、390 CSS 像素窄屏和键盘操作；窄屏二级视图以横向可滚动标签呈现，长日志在自身区域滚动。

## 当前导航实施范围

四个主模块及旧 URL 映射已落地；规则编辑属于数据，已执行策略效果报告与阶段比较/薄弱场景同属分析。共享生成/登记 UI、跨模块活动任务恢复和各阶段通用训练入口按 OpenSpec 任务继续实现；导航归位不代表所有阶段训练能力均已开放。
