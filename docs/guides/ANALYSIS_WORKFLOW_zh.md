# 分析与改进工作流

分析模块包含三个只读/诊断视图：阶段比较、已执行策略效果和薄弱场景。数据规则配置、筛选预览、生成与登记仍由数据模块负责；训练/评测结果以 Runs 中的实际 run 与 artifact 为准。

## 阶段比较

从“分析与改进 → 阶段比较”选择已登记的评测矩阵。只有基准版本、协议、分母和解码设置兼容时才展示数值差异；不兼容或未执行的结果保持原状态，不推测赢家。矩阵 ID 用于恢复具体比较视图。

## 策略效果

从“分析与改进 → 策略效果”查看 `artifacts/data-experiments` 中实际生成的报告。每张报告保留其 `report_id`、`experiment_id`、baseline/对照数据摘要、质量变化、模型指标、可比性状态与局限。直接打开 `?page=policy-effects&report_id=<报告ID>` 可定位单份报告。

保存规则草稿或运行 A/B 数据预览不会生成模型效果；没有训练/复测产物时页面会明确标记“模型效果未评估”。如需修改规则，进入“数据 → 规则对照”；策略报告页不再提供第二套编辑或登记操作，因此查看报告不会重复登记实验。

## 薄弱场景与定向补数

“薄弱场景”按逐题评测与场景报告呈现来源评测、模型、场景和样本分母。选择目标并准备已登记方案后，点击“在数据模块继续生成与审核”。系统自动携带场景、bundle、来源 eval/model/dataset 身份；无需复制内部 ID。数据模块中的生成、样本审核和 canonical 数据集登记共用普通 SFT 的操作组件。

诊断样本仅作为定位证据；生成输入由登记 bundle 中允许的训练 seed 决定，最终 holdout 不进入 prompt 或训练数据。生成登记后，新的 dataset ID 通过自身 manifest/lineage 记录来源关系；重复访问已登记报告不会自动创建第二个数据集。

## 返回路径与安全边界

- 报告、矩阵、场景和对象 ID 由 URL 深链恢复；跨模块只传递显式身份，不继承无关数据筛选条件。
- 活动生成任务可从页面顶部任务条返回；导航、刷新和查看报告都不会启动、取消或重试任务。
- 报告接口失败只影响对应分析视图，并提供重试；规则编辑、数据目录和 Runs 仍是独立模块。
- 比较中缺失的值、样本分母和协议必须按原始 artifact 展示，不补零、不猜测。
