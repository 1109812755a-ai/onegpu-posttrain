# CPT 训练预检说明

Launcher 的 CPT 预检是只读诊断，不会安装 Python 依赖、访问网络下载模型、创建训练 Run 或启动训练。预检通过后，仍需用户显式确认并启动。

## 逐项检查

- **数据集与登记证据**：需要登记 manifest、canonical 文件及摘要、可信处理报告和 `train_seed` 角色。旧 FineMath 数据可先按[历史角色修复指南](CPT_ROLE_REPAIR_zh.md)执行只读预览；仅可信的受支持构建可派生修复版本。普通上传不能自动推断训练/留出角色。
- **固定 Base 配置**：CPT 批准配方引用的 YAML 必须存在于项目内，并声明固定模型引用和 pinned revision。配置缺失、格式错误或路径越界时属于硬阻断。
- **Base 本地权重**：模型目录需要本地 `config.json` 与可识别的权重文件/分片索引。预检不会尝试从 Hub 补下载；缺少配置、权重文件或索引指向的分片时会分别显示阻断原因。请在本机准备完整模型目录，并核对 recipe 中的模型引用与 revision。
- **训练运行环境**：在启动 UI 的同一个 Python 环境中，需要能找到 `swift` 命令。Windows 下优先从项目虚拟环境启动 UI，例如 `\.venv\Scripts\python.exe -m onegpu_posttrain serve-ui --enable-experiment-launcher`。若 UI 已经运行，应先在该环境安装项目声明的训练依赖，再重启 UI，让其重新探测该环境的 `Scripts` 路径。预检不会替用户执行 pip。
- **GPU**：GPU 状态是只读参考信息，无法探测时显示提醒，不等于训练必然失败，也不保证显存足够。实际训练仍可能因 CUDA、显存或驱动状态失败。
- **来源许可与质量**：许可未独立核验、质量报告缺失或报告状态非通过会显示提醒。请自行审阅来源使用权限和质量报告；提醒不等于正式验收通过。

## 启动前核对

处理阻断项后重新运行预检。启动动作会再次核对数据集 ID/摘要、模型配置与本地权重、recipe 和输出身份；预检通过本身不会启动训练。请勿在训练期间关闭 UI 服务。
