# 工作区 UI 规范

适用于数据、训练与评测、Runs、分析与改进。页面仍使用现有浅色、深色、随系统主题；新控件优先使用 `--ux-*` 语义变量，不直接复制某页面的十六进制颜色。

- 一屏先回答“当前对象是什么、处于哪一步、现在能做什么”。每个任务区最多一个主操作，次要入口（日志、lineage、原始配置）放在旁边或可展开区域。
- 请求状态与后台任务分开：`preflight_pending`、`submit_pending` 只表示 HTTP 请求；服务端返回 Run ID 后立即显示 Run 卡；`running`、终态必须以最新 Run 状态为准。网络超时后显示“启动结果待核实”，先查任务，不自动重提。
- 预检令牌失效后主操作是“重新预检”，不能用旧令牌重试。阻断信息在主层给出短句和修复动作；大段原始证据可展开。
- 跨模块共享 `TaskStatusCard` 和 `taskDisplayState`。输入带 `run_id` 时 Run 优先；未知 Run 状态显示“待确认”，不能伪装成功。组件通过 `aria-live` 宣告状态变化。
- 表单控件最小高度 44px；键盘聚焦有可见 3px 轮廓；禁用态明确降低对比并禁止点击；错误字段用 `aria-invalid="true"`。按钮可换行、窄屏不应产生横向滚动。
- 状态色只做辅助：成功/运行用绿色，待确认/提醒用琥珀色，阻断/失败用红色；始终同时显示文字。
