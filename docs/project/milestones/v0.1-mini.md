## Mini data budgets

| Stage | Target |
|---|---:|
| PEFT-CPT | 5M training tokens |
| SFT | 5K complete, verified, parseable and length-eligible examples |
| DPO / original SimPO | 2K verified, length-controlled preference pairs |
| GRPO | 2K verifiable prompts |

Keep train/evaluation problem IDs disjoint, preserve contamination checks, record actual eligible counts, and fail clearly when the source cannot meet a target. Never pad counts by weakening data gates.

For every official Mini dataset/split, emit a linked, versioned `quality_report.json` alongside the dataset manifest. At minimum, record applicable structural checks, stage-specific verification coverage, rejection/yield counts, length/distribution summaries, overlap/contamination evidence, and explicit unavailable metrics. Use the [Data Quality Design](../../design/DATA_QUALITY_DESIGN.md); review candidate gate thresholds against observed Mini distributions and verifier coverage before freezing them. Keep rollout-based GRPO calibration in a separate report tied to the parent model and generation recipe.

Each official data build should also expose its ordered processing steps in the versioned data-build report: source reference, transformations/gates, counts with units, first-rejection reasons and available comparable before/after quality snapshots. Link the final dataset to consuming run/model/evaluation IDs through lineage. A small matched-size cleaning study may be run after the Mini baseline and required OVAT contracts stabilize, but model-effect claims require a registered controlled comparison and are not part of this release gate. See the [detailed processing/effect design](../../design/DATA_PROCESSING_EFFECT_DESIGN.md).

Before Mini/OVAT results are accepted, run `onegpu-posttrain validate-lineage --root <artifact-root> --require-complete` and resolve integrity/incompleteness failures. This is separate from the quality gates: passing lineage validation confirms traceability, not dataset quality or model improvement. Ad hoc plain JSONL remains trainable, but cannot satisfy Mini/OVAT complete-provenance acceptance; external evidence explicitly marked unavailable must be listed in the report.

## Required OVAT experiments

1. **CPT data size:** nested 5M / 10M / 20M token subsets, same source order, Base, recipe and token-budget accounting.
2. **SFT learning rate:** low / mid / high values on the same sample IDs and optimizer-step budget; run the representative mid point with seeds 42 / 43 / 44.
3. **DPO vs. original SimPO:** same M2 hash, preference-pair IDs, seed, PEFT budget and common held-out preference/task evaluations. Keep `cpo_alpha=0` for original SimPO.
4. **GRPO reward design:** accuracy-only versus accuracy + 0.1 × format, holding M2, prompt IDs, profile, generation settings, completions and seed constant. Report reward components separately.

Use the frozen [experiment design](../../design/v0.1.1/04-experiment-design.md) to pin controls, budget semantics, metrics and interpretation. Recommended DPO beta and GRPO generation-count ablations remain optional unless scope is explicitly expanded.
