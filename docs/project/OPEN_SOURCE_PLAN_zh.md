# 开源发布计划

**状态：** 项目级发布计划；未通过验收的版本内容均为规划。  
**许可证基线：** 仓库代码声明 Apache-2.0；第三方数据、模型和依赖仍各自适用其条款。

## 1. 目的

开源是产品要求，不是最后发布代码的动作。每个版本都应让外部用户知道自己运行的是什么、能够在本地复现受支持路径、检查实验依据，并能在不依赖私有基础设施的前提下参与贡献。

本计划按版本定义开源用户体验和发布责任；技术路线见 [ROADMAP](../../ROADMAP.md)、[系统总设计](../design/SYSTEM_ARCHITECTURE_zh.md)和[产品愿景](../design/PRODUCT_VISION_zh.md)。English source: [Open-Source Plan](OPEN_SOURCE_PLAN.md)。

有序数据处理、质量证据和受控模型效果研究的跨版本契约见[数据处理、质量变化与模型效果设计](../design/DATA_PROCESSING_EFFECT_DESIGN_zh.md)。

## 2. 跨版本发布规则

### 许可证与第三方资产

- 仓库当前声明 Apache-2.0；根目录 `LICENSE`、`pyproject.toml`、包元数据和发行说明必须一致；
- 仓库许可证只覆盖项目拥有的代码/文档。外部代码、数据集、模型/tokenizer、benchmark 和生成产物都要单独记录来源及许可，不能暗示它们受 Apache-2.0 覆盖；
- 默认不提交完整上游数据集或模型权重。只有来源和再分发权明确时才提交小型项目自有样例；外部资产通过获取/构建说明提供；
- 维护第三方资产/依赖清单，并在适用条款要求时提供归属声明/NOTICE。公开发布前解决未知或不兼容条款。

### 可复现与证据

- recipe、schema 和评测协议版本化；尽可能记录精确来源版本、解析配置、seed、环境、硬件和 lineage；
- 保留失败/OOM 和限制。示意指标不能当作结果；不得隐去影响解释的分母；
- 只有底层 artifact 可用且文档一致时才发布报告；明确区分 smoke、Mini 和 OVAT 证据；
- 尽可能提供 CPU-safe 的契约/校验路径，并明确哪些步骤需要 CUDA、大规模下载或外部凭据。

### 安全与贡献体验

- 不公开 secrets、可避免的本机私有路径、受限记录或未经审阅的日志/配置转储；
- 保持 `CONTRIBUTING.md`、`CODE_OF_CONDUCT.md`、`SECURITY.md` 和 `CITATION.cff` 准确；记录支持的 Python/依赖版本和硬件预期；
- 改变冻结实验语义必须先更新设计版本；新增 recipe 必须记录数据/model provenance 和泄漏检查；
- W&B 等托管跟踪保持可选；核心 run 应能从本地 artifact 检查。

## 4. 当前仓库准备度

仓库已有 Apache-2.0 `LICENSE`、贡献指南、行为准则、安全政策、引用元数据、Python 包和真实运行 artifact。这是良好基础，但不等于所有依赖/数据/model 资产都已获得再分发许可。

本计划编写过程中发现根目录 `CHANGELOG.md` 曾写着 RTX 4060 实测尚未完成，而实施状态和 Smoke 报告记录已完成；该不一致现已修正。每个版本发布时都要重新核对跨文档一致性。

## 5. 每版本发布检查表

1. 版本号、tag、包元数据、changelog 和 release notes 一致；
2. README/文档区分已支持能力与规划能力；
3. 审查代码、许可证、依赖与资产来源；不包含未许可数据/权重或 secrets；
4. 在干净环境复核安装、样例、校验/测试和已知硬件限制；
5. 每项结果指标都能链接到 run、数据集、模型、评测协议和环境证据；
6. 对应版本涉及的下载、文件访问、进程启动、工具执行等安全行为有边界与测试；
7. 限制、失败/OOM、breaking change 和迁移方式清楚可见；
8. 引用和贡献路径有效；不把可选托管服务误当成核心依赖。

## 6. 范围控制

前期版本以单卡实验室和开源可复现为目标：MVP/v0.1 不要求 Web UI、任务调度器、数据库、Registry、多卡或自动 HPO；UI 保持可选且本地优先。v0.2 才引入受限的本地 launcher，OVAT 确有批量运行需求时再加入串行队列。更重的调度、持久化和部署基础设施放到后续版本，必须由真实用户与工作负载证明价值。

平台级 v1.0 是最终目标，前期只提前沉淀可兼容的 schema、ID、lineage 和 CLI/API 边界，不提前建设平台运维成本。各版本继续支持单卡本地路径；未来 UI/Registry 应可从本地文件、recipe 和 CLI 导出/离开，不让用户失去实验记录。

定向合成数据工作台是提前交付的可选研究/UI 切片，不代表真实远程生成、训练已运行或能力已提升。页面只导出本地未登记配置草稿并读取白名单证据；provider 调用和训练仍由用户显式通过 CLI 执行。fake provider 与项目自有 fixture 仅用于离线契约测试。
