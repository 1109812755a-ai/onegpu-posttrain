# 最终答案核验协议

本文说明 OneGPU-PostTrain 对训练样本最终答案进行独立比对时的状态、资源边界和结论范围。它核验的是抽取出的最终答案与可信 reference 是否等价，不是证明推理过程正确，也不是数据集整体质量审批。

## 结果状态

| 状态 | 含义 | 可否当作错误答案 |
| --- | --- | --- |
| `correct` | 规范化字面相等，或语义验证器确认等价 | 否 |
| `incorrect` | 验证器已成功完成比较，但未确认等价 | 是，仅表示答案不匹配 |
| `unparseable` | 无法解析候选答案或 reference | 否 |
| `unsupported` | reference 类型不支持，或答案超过协议长度上限 | 否 |
| `unverified` | 可选验证器不可用，无法做出结论 | 否 |
| `timeout` | 有界验证批次超过截止时间 | 否 |
| `verifier_error` | worker 或验证器运行失败 | 否 |

只有一次成功完成的比较，才会产生 `correct` 或 `incorrect`。超时、异常、依赖缺失及解析失败均不能记成错误答案。

## 执行与复现

- 精确规范化相等由内置逻辑直接判定；非字面等价使用可选的 `math-verify`。
- 批量语义核验每批最多 32 对，父进程按每批 60 秒设置硬截止；超时会终止并回收该批 worker。
- worker 内关闭 `math-verify` 自带的逐表达式超时，以避免 Windows 上每次 parse/compare 再嵌套创建进程。
- 单个答案或 reference 超过 4,096 字符时报告 `unsupported`，避免异常大的符号表达式进入验证器。
- 使用项目的 `train` 或 `eval` 可选依赖组提供 `math-verify==0.9.0`。缺失时精确匹配仍可用，非字面答案保持 `unverified`；核验过程不访问网络。
- 报告应记录输入摘要、协议、验证器与版本、批大小、截止时间、各状态计数、分母和覆盖率。覆盖率只代表有明确 `correct` / `incorrect` 结论的比例。

## 结论边界

数学等价的最终答案仍可能来自错误或不完整的推理；`correct` 不能单独批准训练数据。官方 Mini 数据还需通过独立的数据质量审查和既定 lineage/readiness gate。验证模式必须显式启用，校准默认仍为严格规范化字面匹配，不会更改 smoke recipe。
